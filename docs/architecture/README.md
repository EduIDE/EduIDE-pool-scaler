## Rules the diagrams only imply

- Session Provisioning and Pool Sizing are custom resource contracts (`Session`, `AppDefinition.spec.targetIdle`); the operator provides them, the Kubernetes API only transports them.
- Claimed instance = its Services/Deployment carry an owner reference to the Session; there is no pool-state label.
- Guardrails and budget live in the Decision Engine, never in a strategy; the engine never goes below the reactive recommendation.
- The service's startup histogram (`application_eduide_session_startup_seconds`) is scraped by monitoring too; it serves the evaluation, not the scaler, and is left out of the component diagram.
- Overrides, scaling decisions and scheduled events are runtime data of the scaler (annotations, metrics, logs, Artemis/calendar input), not stored resources, so there is no object model.
- Checked read-only on the AET cluster (2026-11-16): Rancher Monitoring with Prometheus :9090 and Grafana, API server :6443, shared Envoy Gateway with HTTPS :443, Artemis outside the cluster.
- Decisions (operator vs. scaler split, pull from Artemis, Go, one scaler per installation) are recorded in the plan, not as separate ADRs.
